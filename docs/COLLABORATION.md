# 协作与审查流程

## 角色

| 角色 | 职责 |
|---|---|
| 负责人 | 需求与视觉拍板、内容确认、最终审阅 |
| 主开发（Claude） | 架构、视觉设计、核心交互、真实内容填充、代码审查、合并 |
| 外部协作 Agent | 按技术规格实现脚手架、组件、3D 建模、仿真计算 |

## 外部协作 Agent 的边界

- 只接收技术规格与虚构占位内容；不接收任何个人信息、简历内容、照片、凭据或令牌。
- 不拥有仓库写权限；以压缩包交付，由主开发审阅后提交。

## 交付标准

1. 必须包含源文件：参数化 CAD 脚本（CadQuery）或 STEP + glTF；仿真脚本、网格设置、材料参数、结果数据。
2. 只使用开源工具与开源许可的依赖。
3. 附 README：如何复现、依赖清单、已知限制。

## 审查流程

1. 在隔离目录解压，先通读后运行。
2. 依赖逐个核查（来源、许可、维护状态、安装脚本）。
3. 运行测试与构建；仿真结果与解析估算交叉验证。
4. 通过后以 PR 形式提交，CI 全绿再合并。

## Git 规范

- GitHub Flow：`main` 始终可部署；功能分支 `feat/*`、`fix/*`、`docs/*`。
- 提交信息遵循 Conventional Commits。
- 版本号遵循 SemVer，发布时更新 CHANGELOG 并打 tag。
