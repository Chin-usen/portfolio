## Performance-gate follow-up: font-induced English header shift

The first full mobile Lighthouse run found a separate first-paint defect after the settled-state visual reviews: all eight English non-S1 routes scored 86-89 because web fonts moved the language selector to a second row. A controlled font hold/release measured the main region moving 85 to 145 px, with CLS 0.247041. Chinese and S1 headers did not reproduce this shift. The original failed measurements are preserved in `lighthouse/attempt-1/`.

A narrowly scoped mobile rule reserves the existing final English language row before fonts load. No font, color token, navigation markup, JavaScript, content or settled 390 px layout is changed. Three new regressions check all eight affected routes with delayed fonts, keyboard menu operation and all five navigation links without JavaScript. Actual closure measurements in `ci/header-font-stability.json` show all eight routes at mainTop 145 px and languageTop 80 px both before and after fonts load, with zero measured movement and no horizontal document overflow. Final mobile Lighthouse passed all 18 routes / 54 measurements: route Performance medians 90-100; Accessibility and SEO were 100 in all 54 runs. Original median thresholds are unchanged. Scores and every run hash are recorded separately in `lighthouse/summary.json`. This performance follow-up does not rewrite the original independent A/B scores or pretend they inspected this first-paint state.
