# Independent laboratory pages (contract version 1)

The 1.4.0 base discovers pages without a shared import or routing edit. Each page owns `src/components/lab/<slug>/Page.astro` and `page.json`, two `src/content/lab/{zh,en}/<slug>.md` entries, `public/models/<slug>/`, its tests, and `changes/<slug>.md`. Its `page.json` is also the single lab-list registration. Do not update the version, central changelog, another laboratory page, docs, or thermal-p2 in a standalone page patch.

`Page.astro` receives `{ locale, entry }`. The descriptor contains `contractVersion: 1`, `slug`, unique `code` (L2, L3, etc.), `template` (`disassembly` or `simulation`), `bodyClass`, and `fonts: { commonNoto, mono, preload?: { zh?: string[], en?: string[] } }`. Only local WOFF2 URLs are accepted. New page fonts belong under `/models/<slug>/fonts/`; generated font CSS and any font-generation hook belong inside that page's component directory. Existing L1/S1 retain their legacy directories and URLs.

Localized content is the title/summary/list authority. New disassembly markdown frontmatter has a nonempty `parts` array of `{ id, name, secondaryName?, short, role, features, material, order }`. Every part has the same stable id and order in both locales. Name/role/features/material are actual Content Collection fields, not unchecked client JSON. Duplicate ids, missing locales, template/kind disagreement, duplicate codes, missing entry components and path escapes fail the build. Keep placeholder attribution and generic textbook structures; no specific product replication.

Use the shared disassembly shell/cards/controller and viewer lifetime helper. Domain geometry, animation, equations, assumptions and add-on cards remain in the page directory. Simulation pages use the shared S1 shell/card boundaries and their own evaluator. S2 reads `model/l1-half-bridge/params.json` directly and records its hash; do not copy its dimensions or alter thermal-p2. Optional sibling-page links must work when that sibling patch is absent.

Page-owned asset scripts use fixed paths `model/generate.mjs`, `model/verify.mjs`, and optional `model/fonts.mjs`. Run `pnpm model:lab <slug>`, `pnpm model:lab:verify <slug>`, or `pnpm model:lab:verify --all`; optional font preparation uses `node scripts/lab-assets.mjs fonts <slug>`. Scripts receive `--evidence <outside-repository-path>` unchanged (with a per-slug directory for --all). Each hook runs in a separate pinned Node process. An ordinary build consumes checked-in assets and never invokes FEM or rendering. Verification must distinguish actual numerical/geometry reproduction from hash-only checks.

Record model source hashes, tools/licenses, geometry units/axes, independent part node names, compressed GLB size, WebP dimensions and asset SHA-256 in the page manifest. Every page remains below 1.5 MB compressed glTF. Actual GLB-based static WebP must remain available without downloading GLB on reduced-motion/low-resource fallback. Dispose pending loads, observers/listeners, all owned Three resources and the native WebGL context on route exit. Maintain keyboard selection, parts, equations and computed results in static mode.

Nested `tests/unit/**/*.test.ts` and `tests/e2e/**/*.spec.ts` are discovered automatically. CI discovers model hooks and new registered page URLs. New pages receive three mobile Lighthouse samples per locale, P >= 90, A >= 95 and LCP <= 2499 ms. Keep meaningful lifecycle evidence for ten page/Home round trips, reduced-motion/weak-device fallback, pending loads and native context disposal.

The shared generated `src/styles/generated-fonts.css` is ignored and recreated by dev/build/typecheck from installed source text. Do not include that derived file in a page patch. Original font files and licenses stay checked in; exact page subsets must preserve original glyph outlines/metrics and include all runtime copy/weights.

Deliver `git format-patch --binary` against the final 1.4.0 release commit, generated assets, concise checks/Lighthouse median summary, pinned Impeccable audit/critique before/after, and desktop/mobile screenshots. Prove each patch applies on the base independently and together in different orders. Keep each attachment <= 1 MB and provide a START archive with SHA-256 manifest; file upload alone is not completed delivery.
