# Busbar Joule heating simulation page (S2)

Adds the bilingual S2 lab page `/lab/busbar-joule-heating/` on the shared S1 simulation shell and styles. It shows the DC Joule heating of the L1 half-bridge P layer, AC link and N layer for two switching states (S_H on: DC+ → P layer → S_H → AC link → AC; S_L on: AC → AC link → substrate 2 → S_L → N layer → DC−). A topology diagram follows the state; no shoot-through case is calculated. Inputs are current 50–400 A, conductor thickness 0.5–3 mm, strap width 2–6 mm, Cu C1020 / Al 1060 / custom σ and k, convection h 5–500 W/(m²·K) and the substrate temperature T_sub 40–100 °C at the soldered pins. Outputs are the peak temperature, Joule loss, equivalent resistance, a loss breakdown and 3D temperature / current-density fields with the S1 colouring, section and hover readout. Boundary conditions, scaling formulas and exclusions (no chip losses, skin effect or temperature coefficient of resistivity) are stated on the page.

Geometry is read at run time from `model/l1-half-bridge/params.json` (no copied dimensions); its SHA-256 is recorded in the surrogate and model manifest. An offline self-written numpy/scipy FEM (trilinear hexahedra; electric potential, then steady conduction with the Joule source) produced 276 training and 60 independent test samples. The browser evaluates only the exported Gaussian-process scalars and POD fields; current, σ and k scale exactly. Analytical checks (straight-bar R = ρL/A, 1-D conduction rise), a three-level mesh-convergence study and geometry-grouped cross-validation are committed under `src/components/lab/busbar-joule-heating/model/fem/` with the scripts, data and regeneration notes.

Touch devices keep the rendered static preview and load WebGL only after "Load 3D model". Reduced-motion, save-data and low-resource devices use a Canvas 2D plan view with the same field, selection and readouts; WebGL failure or context loss switches to it. The page owns its Noto subsets under `public/models/busbar-joule-heating/fonts/`. No shared component, other page, version, docs or CI file changes.

## Mobile LCP follow-up

The static preview gains a 480 × 300 WebP (rendered by `model/render.mjs` and recorded in the manifest); `sizes` selects it on phone-width viewports. It remains an `<img>` in the server HTML with `fetchpriority="high"` and no lazy loading. The regular Chinese weight is split into a first-paint face and a deferred face with disjoint unicode ranges. The reference sections (current path, boundary conditions, conductor notes) now follow the parameter workspace at full width and, with the model notes and footer, use `content-visibility: auto`, so their glyphs load when scrolled near. Emphasis faces still cover only their CSS-mapped strings. The interaction bundle loads at idle after the server-rendered result has painted.
